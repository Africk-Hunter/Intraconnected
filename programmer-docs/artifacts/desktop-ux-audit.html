Desktop UX Audit

Overview

The desktop app works well with a mouse and has almost nothing for the keyboard, no undo, and one URL for every level. Four small bugs should be fixed before anything else; one of them can silently erase a card's link.

Findings come from reading the desktop code against the principles in the saved Desktop UX Principles doc. Nothing was run in a browser, so appearance claims are marked for a visual check.

Biggest gaps users will feel

  1. Deleting or moving a branch cannot be undone (A1).
  2. No keyboard path to open, rename, move or delete a card (A2, A3).
  3. Refresh or Back loses your place; the URL never changes (A6).
  4. Esc and Enter do nothing in most modals (A5).
  5. Dragging is the only way to move a card (A4).

Bugs and misleading UI

  • Link modal can erase a link
  • Drop on a link card looks valid, does nothing
  • Blank idea can be created
  • Cards take focus but ignore Enter

How this was checked

Read: pages/Idea.tsx, components/IdeaNode.tsx, Navbar.tsx, MindMap.tsx, TooltipButton.tsx, DepthIndicator.tsx, Trash.tsx, LastIdea.tsx, AnimatedOverlay.tsx, the Rename, Link, Delete, Creation, Checklist and Onboarding modals, Help.tsx, IdeaContext.tsx, useModalFocusTrap.ts, plus the idea store and creation helpers.

Effort labels (S, M, L) are my estimates, not measured. S is under an hour, M is a day or less, L is several days.

Each finding has a tag: Bug behavior that is wrong, Gap something users expect and don't get, Polish wording or small affordance.

Fix first

Small changes that remove surprises. None needs a design decision.

F1

Link modal can erase a card's link

BugS
Users expect

Opening "Change link" shows the current link, and pressing Change without editing keeps it.

Today

LinkChangeModal.tsx:22-25 shows currentLink as the textarea's initial text but never copies it into modalContent. The Change button saves cleanLink(modalContent). Rename and Creation both reset modalContent to '' on close, so an untouched Change saves an empty link.

Cancelling after typing also leaves that text in modalContent for the next card.

Change

Seed modalContent from currentLink when the modal opens, as RenameModal.tsx:19-30 already does for names. Submit on Enter, close on Esc.

useEffect(() => {
  if (linkChangeModalOpen) setModalContent(currentLink);
}, [linkChangeModalOpen, currentLink]);
Caveat

Found by reading the code, not reproduced. Worth a 30-second manual test: add a link, reopen it, press Change.

F2

Dropping on a link card looks valid but does nothing

BugS
Users expect

A target that can't accept the drop doesn't light up. Principle: show a "not allowed" state over invalid targets.

Today

Link cards stay droppable (IdeaNode.tsx:379-382 only disables checklists, notes and mobile), so they get the dashed border and 1.15 scale. On release Idea.tsx:310-312 returns early with no message. The card snaps back and nothing explains why.

Change

Add link !== '' to the disabled condition so the card never highlights. Optionally show a short "Links can't hold ideas" hint when a card hovers one.

F3

A blank idea can be created

BugS
Today

Checklist and Note disable Create until the title has text (CreationModal.tsx:442, 451). The Idea tab's Create is always enabled, and handleCreateIdea (line 213) and handleIdeaCreation (creation.ts:12) don't check. An empty card counts toward the 50-idea free limit.

Change

Disable Create while modalContent.trim() is empty, same as the other two tabs. Add Ctrl/Cmd+Enter to create (see A5).

F4

Cards take keyboard focus but do nothing

BugS
Today

dnd-kit's attributes (spread at IdeaNode.tsx:763, 833, 902) give each card role="button" and tabIndex=0. Only PointerSensor is registered (Idea.tsx:431) and there is no key handler, so Tab lands on a card and Enter or Space do nothing. Keyboard users get a focus stop with no action.

Change

At minimum, Enter on a focused card opens it (same as click). The full model is in A2.

Remove or replace

Things that exist today and work against what users expect.

R1

Replace the confirm dialog on every delete

GapM
Users expect

Delete happens at once and an Undo toast appears. Confirmation dialogs are for actions that can't be undone, because people click through them out of habit (NN/g). Material toasts stay 4–10 seconds (Material).

Today

Drop on trash → DeleteConfirmModal → delete. The text is "Delete 'name' and all of its children?" with no count, and the Delete button isn't focused, so Enter does nothing. The delete returns the removed ideas (ideaStore.ts:86) but DeleteConfirmModal.tsx:12 throws them away.

Change

Match mobile: a card with no children deletes immediately with an Undo toast. A branch keeps one confirmation that states the count ("Delete 14 ideas"), then also offers Undo. Undo calls restoreIdeas(removed), which already exists.

R2

Replace the hover-only copy, rename and link icons

GapM
Users expect

Row actions behind a visible ⋯ button and a right-click menu. Actions that appear only on hover are missed, and unusable for keyboard, eye-tracking and pointer-assist users.

Today

Three small icons (link, pencil, copy) fade in at 50% opacity on card hover (idea.scss:693). They are the only way to rename, edit a link or copy. There is no right-click menu (no onContextMenu anywhere in src).

Change

One visible ⋯ button per card plus right-click, opening the menu in A3. Keep the hover icons only if they are also reachable by keyboard. Mobile already uses ⋯ on every row, so this also closes a cross-platform gap.

R3

Replace the depth dots with a breadcrumb trail

GapM
Users expect

A readable path (Ideas › Project › Task) where each part is a link and the current level is plain text. Hierarchy, not history (NN/g). Workflowy shortens long paths to "···" (help).

Today

DepthIndicator.tsx renders an empty box per level in the right sidebar. The name shows only on hover (font-size animates from 0, depth.scss). Each is a div with onClick: not focusable, no label for screen readers. Back, Home and the dots are three separate "go up" controls.

Change

A breadcrumb row above the title, built from rootIdStack, with real buttons. Keep Back and Home. Delete the dots and the Help screen that explains them.

R4

Replace the one-click priority cycle with a picker

PolishS
Today

Clicking the ribbon cycles none → Low → Medium → High → none (IdeaNode.tsx:672). Reaching High takes three clicks, with a re-sort pending until the pointer leaves the card. The ribbon is a narrow target, and its tooltip is the native title.

Change

Put Priority in the ⋯ menu (None / High / Medium / Low), as mobile does. Keep the ribbon as a display, optionally clickable to open the same menu.

R5

Clarify the Sort button and the clickable title

PolishS
Today

The Sort button reads "Priority" or "Age", which is the current state, not the action, and "Age" doesn't say which end comes first (the code sorts oldest first). The title bar is styled like a button and opens Rename when clicked (Idea.tsx:454), with no pencil or tooltip, and does nothing at the top level.

Change

Label the sort "Sort: Priority" / "Sort: Oldest first". Add a pencil to the title below the top level, or make it editable in place, and bind F2 (A2).

Add

Behaviors users bring from other apps that the desktop app doesn't have yet.

A1

Undo for delete and move (Ctrl/Cmd+Z and a toast)

GapM
Users expect

Ctrl/Cmd+Z reverses the last structural change. Every outliner and file manager works this way.

Today

A drop on a card or the parent zone calls updateIdeaParentId (Idea.tsx:306-316) with no record of where it came from. Delete is covered by R1. Undo exists only on mobile (MobileUndoToast).

Change

A small undo stack of the last action (delete → restoreIdeas, move → previous parent) shown as a toast for about 5 seconds and bound to Ctrl/Cmd+Z when focus isn't in a text field. Reuse the mobile toast logic.

A2

Keyboard navigation and shortcuts

GapM
Users expect

Arrow keys move between cards, Enter opens, F2 renames, Del deletes, and mind-map tools use Tab for a child and Enter for a sibling (MindNode, Miro, MindMup). A ? key lists the shortcuts.

Today

No global key handling on the main screen. The only listeners are in the Help panel (arrows, Esc) and inside text fields. Help.tsx:90 already guards against firing while typing, so that pattern exists.

Change

Single-key shortcuts (N, ?, Backspace) must not fire while a text field is focused, and nothing should override browser shortcuts. Show each key in its button's tooltip and in the ⋯ menu.

A3

Right-click menu and ⋯ button on every card

GapM
Users expect

Right-click on an item shows what you can do with it. In GitLab's research, users right-clicked first when looking for rename and delete (issue). Menus should also be reachable without right-click, stay under 10–12 items and show shortcuts (NN/g).

Change

Same items as mobile's actions sheet, with keys beside them: Open · Rename (F2) · Edit link · Priority ▸ · Copy · Move to… (A4) · Delete (Del). Checklists add "Open full view"; notes omit Open and Edit link.

A4

"Move to…" picker as an alternative to dragging

GapM
Users expect

Workflowy has a Move-to picker (Alt+Ctrl+M). WCAG 2.5.7 requires every drag to have a click or keyboard alternative (WCAG).

Today

Moving a card is drag-only on desktop. Cards sit in a grid, so a long drag to a far branch needs the "move to parent" zone and several steps. Mobile has MobileMoveSheet.

Change

A modal with a searchable tree of valid targets (no links, checklists, notes, or the card's own subtree), opened from the ⋯ menu or a shortcut. Drag stays for quick moves.

A5

Esc, Enter and focus handling in every modal

GapM
Users expect

Esc closes the dialog, Enter confirms single-line ones, focus stays inside, and returns to the button that opened it (ARIA dialog pattern).

Today

The focus trap exists only for Checkout and Upgrade. useModalFocusTrap.ts:6-9 notes it was kept out of AnimatedOverlay to avoid changing every modal at once.

Change

Move the trap, Esc and focus return into AnimatedOverlay and test each modal once. Then per modal: Rename and Link submit on Enter (Shift+Enter for a new line); Create submits on Ctrl/Cmd+Enter; Delete focuses the safe button first. Esc acts as Cancel everywhere; in Create it can ask first if text was typed.

A6

One URL per level: Back, refresh and deep links

GapM
Users expect

The address bar reflects where you are. Browser Back goes up a level, refresh keeps your place, and a copied link opens the same level. Rule of thumb: if someone would bookmark it, it belongs in the URL.

Today

Every level is /main. rootId is plain state starting at 1 (IdeaContext.tsx:69) and navigateToId only changes state (lines 98-115). So Back leaves the app or goes to the sign-in page, and refresh returns to the top level.

Change

Make the level part of the route (/main?idea=ID or /main/:id). navigateToId pushes an entry; a popstate listener sets rootId; on load read the id and fall back to 1 if it no longer exists. Keep one source of truth (the URL).

Not needed

A "leave site?" prompt for unsynced edits. The sync outbox is stored in localStorage, so closing the tab doesn't lose queued changes.

A7

Search and quick jump (Ctrl/Cmd+K)

GapL
Users expect

Workflowy, Notion, Linear and Slack all open a search box on Ctrl/Cmd+K. Many people don't know the key exists, so also give it a visible entry point (Chameleon).

Today

I found no idea search on desktop. The mind map is the only way to see ideas outside the current level, and it is read-only.

Change

A palette that searches idea text across all levels (fetchFullIdeaList() is already a local read) and jumps to the match's parent, highlighting the card. Later it can also list commands (New idea, Toggle mind map). Largest item here, but it matters most as the tree grows past the free 50.

A8

Mind map controls: zoom buttons, fit, Esc to close

GapS
Today

MindMap.tsx has no buttons, no Ctrl +/−/0, no "fit to screen", and no key to close it (toggle button only). After panning or zooming away there is no quick way back to the current idea.

Change

Small − / + / "fit" / "center on current" buttons, Ctrl +, −, 0, Esc to close, and arrow keys to pan. Re-centering already exists internally (the effect at line 184), so "center" is mostly wiring.

A9

Tooltips on keyboard focus, with shortcuts

PolishS
Today

TooltipButton.tsx:23 shows the tooltip only after a 1000 ms hover and never on focus. Card icons use the native title attribute instead, so the two look and time differently.

Change

Show on focus as well as hover, shorten the delay for the five nav buttons, and append the shortcut ("Create new idea (N)"). Use the same component for card icons. No authoritative standard exists for the delay, so pick one by feel.

Needs a visual check

Code reading can't settle these. Each is a quick look in the browser:

  • Size of the hover icons and the priority ribbon against the 24×24 px minimum (WCAG 2.5.8).
  • Visible focus ring on cards, nav buttons and modal controls. Only the tooltip highlight in navbar.scss sets one that I found.
  • Layout at 1366×768 and 1536×864, and at 200% browser zoom.
  • Whether the Rename textarea selects its text on open.
Not covered: mobile (separate UI), landing and pricing pages, checkout, Profile screens beyond Esc and focus handling, and the sync engine.
