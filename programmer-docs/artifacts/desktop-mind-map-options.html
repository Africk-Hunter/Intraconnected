Desktop mind map: keep, change or cut

Hunter is leaning toward removing the mind map from desktop because the sidebar feels cluttered and the map seems like a nice look more than a tool. This page lays out the alternatives so the call is made on trade-offs, not on a hunch.

Intraconnected2026-10-11branch mainbase commit 861249a

Overview

Nothing has been removed. An earlier attempt at deleting the map was reverted, and the code is back as it was (see State of the repo).

The decision comes down to one question: is the map a feature you want to invest in, or one you want to stop carrying? There are four honest answers.

  • Keep it as is. Cheapest, but the clutter stays.
  • Declutter it. Same feature, lighter footprint in the sidebar.
  • Make it earn its place. Add things search cannot do, so it stops being a "glorified search".
  • Remove it from desktop. Smallest surface, but you lose the whole-tree overview and the product's signature image.

Short version: decluttering is nearly free and fixes the stated complaint. Whether to also invest in features depends on how much you want the map to be the app's identity on desktop. Removal can wait until you have tried the other two.

What it is today

On desktop the map is a full-screen overlay opened from the pink button in the left sidebar. It draws the whole idea tree as nested columns with connector lines, supports pan, zoom and center, and jumps to a node on click. The node you are in is marked brown. Ideas, links, notes and checklists each have their own look.

  • Overlay component: src/components/MindMap.tsx (377 lines) and src/styles/mindmap.scss (349 lines).
  • Open state lives in Idea.tsx as showMindMap. While it is open, the create and home buttons and the trash hide and the main grid fades out.
  • Entry points: the sidebar toggle, and the "Toggle mind map" command in the Ctrl/Cmd+K palette.
  • It has its own keys (zoom, center, pan) listed in the shortcuts modal, and useDesktopShortcuts pauses the card keys while it is open.
  • Help page four, "The Mind Map", is entirely about it.
  • Mobile has a separate map sheet (MobileMindMapSheet) that shares none of the desktop component, so changes here do not touch the phone.

The landing page hero animation also draws a mind map, so the marketing image would no longer match the desktop app if the map went away.

The four options

Option A

Keep as is

No work. The sidebar keeps five buttons on the left and the clutter complaint stands.

Option B · low effort

Declutter

Keep the overlay, take the button out of the main sidebar. Open it from the command palette, a shortcut and the breadcrumb root instead.

Option C · real work

Make it distinct

Add views search can never give: filters, progress, recency, drag to reparent. It becomes a tool, not a picture.

Option D · one-way

Remove from desktop

Delete the overlay, its toggle, keys, help page and styles. Mobile keeps its map.

B and C combine well: declutter first, then add features only to the ones you will actually use.

Features that would set it apart

Each of these answers a question search cannot. Effort is a rough guess against the current component, which renders from fetchFullIdeaList() and has no timestamps beyond the idea id (ids are creation times).

Priority lens

One toggle dims everything except priority 1 and 2 across the whole tree. Answers "what is urgent anywhere?"

Effort: small. Data already on each idea.

Recency lens

Tint nodes by how recently they were created, using the id. Shows what you have been working on and what is stale.

Effort: small. Edits are not tracked, only creation.

Checklist progress on nodes

Show 3/7 on checklist nodes and a rolled-up count on their parents.

Effort: small to medium.

Find on map

Search box inside the overlay that highlights and centers matches instead of opening a list.

Effort: small. Reuse idea/search.ts.

Drag to reparent

Drag a node onto another to move it, with the existing undo. The one thing that turns it from a viewer into an editor.

Effort: medium. Route through useIdeaActions().moveIdea.

Branch focus

Open the map on the current branch only, with a button to widen to everything. Large trees stop being a wall.

Effort: small.

Export as image

Save the map as PNG or SVG for sharing or printing. Gives it a use outside the app.

Effort: medium.

Free-form canvas

Let nodes be placed by hand and remember positions. This is the classic mind-map tool, and a large step.

Effort: large. Needs a new synced field.

If you only pick two, take the priority lens and drag to reparent. They are the clearest "this is not search" answers for the least work.

Decluttering the sidebar

The clutter is about the button, not the overlay. Options for getting it out of the way without losing the feature:

  • Shortcut plus palette only. Add a key (for example G, free in the shortcuts list) and keep the existing palette command. The sidebar drops to create, home and search.
  • Breadcrumb entry. A small map icon at the start of the breadcrumb, where "where am I in the tree" already lives.
  • Move it to the right sidebar next to help and patch notes, treating it as a view rather than an action.

Whichever you choose, the help page and shortcuts modal should name the new entry point, since they currently point at the sidebar button.

Recommendation

Do B now, decide on C after living with it, and hold D. Moving the button out of the sidebar addresses the clutter you described at almost no risk. If a few weeks pass and you never open the map, that is real evidence for removing it. If you want it to be a selling point on desktop, add the priority lens and drag to reparent first.

A test worth running before cutting: open the map on your own tree and ask whether it ever showed you something you did not already know. If not, your tree may simply be small, and the map matters more for the trees of heavier users.

Open questions

  2. Is the map part of how Intraconnected is sold on desktop (landing page, store listing), or only on mobile?
  3. Which entry point do you prefer for option B: shortcut and palette, breadcrumb icon, or right sidebar?
  4. If you do add features, do you want the map to become an editor (drag to reparent) or stay a viewer?
