# Audit — Intraconnected (whole repo, 2026-10-07)

## Summary
The project is in good shape. Typecheck is clean, all 177 tests pass, and the Firestore rules, webhook signature check, event dedupe and sync outbox all hold up. What matters most is in billing. The server's "already paid" checks read Firestore, which doesn't change until the webhook arrives, so a user who pays twice in that gap is charged twice (#1). Lifetime accounts can also be sold an Annual subscription that does nothing (#2). Account deletion has two gaps: it accepts any valid ID token without a recent sign-in (#3), and it goes ahead even if cancelling Stripe failed (#4). On structure, the payoff is in one write path for idea changes and one shared folder for code the client and server both need.

Known items E1–E9 and "checkout orphans" from `launch-checklist.html` are not repeated here.

## Findings

### 1. [High · Bugs/Billing] Paying twice before the webhook lands charges twice
**Where:** [create-payment-intent.ts:121](../../netlify/functions/create-payment-intent.ts#L121) (Lifetime) and [:155](../../netlify/functions/create-payment-intent.ts#L155) (Annual)
**What happens:** Both duplicate-purchase guards read `meta/billing`, and only the webhook writes that doc. Example: a user completes Annual payment, the modal shows "still finalizing", and they reopen checkout before `customer.subscription.updated` arrives. `subscriptionStatus` is still `null`, so a second subscription is created and paid. The webhook then tracks only the latest subscription. The first one renews every year, can't be cancelled self-serve, and survives account deletion. Lifetime has the same race. The second `payment_intent.succeeded` overwrites `lifetimePaymentIntentId`, so the first charge can no longer be refunded self-serve either.
**Fix:** Ask Stripe, not Firestore. Before creating, `stripe.subscriptions.list({ customer, status: "all" })` and reject (409) if any subscription is `active`/`trialing`/`past_due`. Reuse an `incomplete` one instead of creating another, which also closes the checklist's "checkout orphans" item. For Lifetime, `paymentIntents.search({ query: "metadata['firebaseUid']:'<uid>' AND status:'succeeded'" })` before creating.

### 2. [Medium · Bugs/Billing] Lifetime accounts can be sold an Annual subscription
**Where:** [create-payment-intent.ts:155](../../netlify/functions/create-payment-intent.ts#L155)
**What happens:** The Annual guard checks only `subscriptionStatus`, which is `null` on a Lifetime account. A direct call, or the Annual card showing before `billingPlan` loads, creates a real subscription. If it's paid, the user is charged every year for nothing: `customer.subscription.updated` no-ops on Lifetime ([billingEvents.ts:157](../../netlify/functions/lib/billingEvents.ts#L157)), so the subscription is never recorded and `cancel-subscription` can't find it. **Unverified:** if Stripe reports an abandoned checkout's expiry as `customer.subscription.deleted`, the Lifetime branch at [billingEvents.ts:209](../../netlify/functions/lib/billingEvents.ts#L209) rewrites `updatedAt`. That restarts the 14-day refund window on demand, which turns E2 from drift into something a user can trigger. To confirm, run one test-mode checkout, abandon it, and check the event log after 23h.
**Fix:** `if (billing?.plan === "lifetime") return jsonError(409, "You already have Lifetime access.")` before the Annual branch. Do E2 (`lifetimePurchasedAt`) as well.

### 3. [Medium · Security] Account deletion doesn't require a recent sign-in on the server
**Where:** [delete-account.ts:44](../../netlify/functions/delete-account.ts#L44)
**What happens:** The password re-check runs only in the client ([authFirebase.tsx:38](../../src/utilities/firebase/authFirebase.tsx#L38)). The function accepts any unexpired ID token. Anyone holding one (from a borrowed or unlocked device's session, or any script running on the origin) can `POST /delete-account` and permanently wipe the account without the password.
**Fix:** Verify with `verifyIdToken(token, true)`, which checks revocation, and reject if `Date.now()/1000 - decoded.auth_time > 300`. `reauthenticateWithCredential` already issues a token with a fresh `auth_time`, so the client needs no change.

### 4. [Medium · Bugs/Billing] Deleting an account goes ahead when Stripe cancel fails
**Where:** [delete-account.ts:63-72](../../netlify/functions/delete-account.ts#L63-L72)
**What happens:** A transient Stripe error is logged and deletion continues. The Auth user and billing doc are gone, but the subscription keeps charging the card every year. Its later webhooks also re-create `users/{uid}/meta/billing` for a user that no longer exists.
**Fix:** Continue only when the cancel succeeds or Stripe says it's already gone (`resource_missing`, or status `canceled`). Otherwise return 502 so the user can retry. The rate limit allows 3 tries a day.

### 5. [Medium · Security] An imported JSON "backup" can add a `javascript:` link
**Where:** [importers.ts:485](../../src/utilities/idea/importers.ts#L485) → [importers.ts:720](../../src/utilities/idea/importers.ts#L720) → `window.open` in [IdeaNode.tsx:415](../../src/components/IdeaNode.tsx#L415), [MindMap.tsx:61](../../src/components/MindMap.tsx#L61), [MobileMindMap.tsx:636](../../src/components/MobileMindMap.tsx#L636), [MobileMindMapSheet.tsx:103](../../src/components/MobileMindMapSheet.tsx#L103)
**What happens:** Every other importer filters links through `isWebLink`. The Intraconnected JSON path copies `idea.link` through unchecked, and `window.open` isn't covered by React 19's `href` sanitising. A shared file with `"link": "javascript:…"` becomes a clickable idea. **Unverified:** whether the popup's script runs with the app's origin depends on how the browser handles `noopener`. If it does, it can read `dek_local` and the plaintext `ideas` cache. `'unsafe-inline'` in the CSP doesn't block `javascript:` URLs. Separately, `cleanLink` lets any `scheme://` through, including `javascript://%0A…`, but only for links the user types themselves.
**Fix:** Apply `isWebLink` at line 485 and on `keepLink`. Add one `openIdeaLink(url)` helper that refuses anything that isn't `https?:`/`mailto:`, and use it at all four call sites. Make `cleanLink` allow only `http`/`https`/`mailto`.

### 6. [Medium · Security] Rate limits can be bypassed by parallel requests; feature requests spend the GitHub token
**Where:** [rateLimit.ts:26-34](../../netlify/functions/lib/rateLimit.ts#L26-L34), [submit-feature-request.ts:58-90](../../netlify/functions/submit-feature-request.ts#L58-L90)
**What happens:** Both read the hit list, then write it back with no transaction, so 20 simultaneous requests all see "under the limit". For `submit-feature-request`, that means 20 GitHub issues opened with the server's token, then again from a new account, because sign-up is unlimited and this endpoint doesn't require a verified email. The billing endpoints also go through the same race, but Stripe's own checks absorb the duplicates.
**Fix:** Wrap the read and write in `firestore().runTransaction`. In `submit-feature-request`, use `verifyIdTokenDetailed` and require `emailVerified`.

### 7. [Medium · Bugs · Unverified] Deleting a very large subtree may pause sync permanently
**Where:** [parsing.tsx:27-31](../../src/utilities/idea/parsing.tsx#L27-L31) → [outbox.ts:390-393](../../src/utilities/sync/outbox.ts#L390-L393)
**What happens:** A subtree delete becomes one op, and one op becomes one `writeBatch` (N deletes plus 2 meta writes). An import adds up to 2000 ideas under a single top-level idea, so deleting that idea is a single batch of about 2000 writes. If Firestore still enforces 500 writes per batch, this returns `invalid-argument`, which is classed as permanent. The outbox pauses with "It may be too large", and **Try again** fails the same way every time. `delete-account.ts:17` assumes the 500 cap applies. Google's current limits page says otherwise in places. To confirm, delete a 600-idea import against the real project.
**Fix:** Split in `batchDeleteIdeasFromFirebase` into ops of ≤ 450 ids each. This is safe either way, and each op stays idempotent.

### 8. [Low · Bugs] Sign-in doesn't trim the email; sign-up and reset do
**Where:** [Auth.tsx:167](../../src/components/Auth.tsx#L167) (compare lines 113 and 151)
**What happens:** Phone keyboards often add a trailing space after autocompleting an address. Sign-in then reports "Invalid email or password" for correct details.
**Fix:** `signInWithEmailAndPassword(auth, email.trim(), capturedPassword)`.

### 9. [Low · Bugs] The auth listener in `Auth.tsx` re-subscribes on every render
**Where:** [Auth.tsx:29-37](../../src/components/Auth.tsx#L29-L37)
**What happens:** The effect has no dependency array, so each keystroke tears down `onAuthStateChanged` and subscribes again. Each new subscription fires immediately and re-runs `loadDEKFromSession()`. Today this is wasted work, but it can fire a `/main` redirect in the middle of a sign-in once `isSigningIn` is reset.
**Fix:** Add `[]`.

### 10. [Low · Bugs] The cached plan carries over to the next account on the same browser
**Where:** [firebaseHelpers.tsx:6](../../src/utilities/firebase/firebaseHelpers.tsx#L6). Sign-out ([authFirebase.tsx:16](../../src/utilities/firebase/authFirebase.tsx#L16)) doesn't clear it.
**What happens:** After account A (Lifetime) signs out, account B (Free) reads `billing_plan = lifetime` until its billing snapshot arrives. During that window `canCreateIdea()` lets B past the cap, and `sendOp` skips B's `nodeCount` increments. The once-per-session resync usually repairs the count, so the main effect is a confusing UI moment.
**Fix:** Store the cache as `billing_plan_<uid>`, or remove it in `signUserOut`.

### 11. [Low · Security] Dependency advisories
**Where:** `package-lock.json`
**What happens:** The critical `websocket-driver` comes from `@firebase/database`'s Node transport. The app doesn't use Realtime Database, and browsers use native WebSocket. The high `@grpc/grpc-js`/`@firebase/firestore` advisories are also Node-only paths. `@fastify/busboy`, `brace-expansion` and `source-map-js` are tooling. Nothing reachable from a browser or a function request.
**Fix:** Run `npm audit fix`, not `--force`. The "fix" npm suggests for `firebase` is a downgrade to v9; ignore it.

### 12. [Medium · Structure] Every idea change takes two separate calls, and the mobile copy has already drifted
**Where:** [storage.tsx](../../src/utilities/idea/storage.tsx), [creation.tsx](../../src/utilities/idea/creation.tsx), [firebaseHelpers.tsx:116-151](../../src/utilities/firebase/firebaseHelpers.tsx#L116-L151), callers across components
**What happens:** Most changes need `updateX()` (localStorage) and then `updateXInFirebase()` (outbox), called by hand at each call site. `updateIdeaParentId` does both, and calling the second one too double-writes. Three of CLAUDE.md's "Critical Gotchas" exist only to document this. [MobileMindMap.tsx:789-792](../../src/components/MobileMindMap.tsx#L789-L792) already builds and saves a standard idea inline instead of calling `handleIdeaCreation`. It works today only because Mobile checks `canCreateIdea()` earlier, in `addChild`.
**Fix:** Add one `ideaStore.ts` where each mutation (`createIdea`, `rename`, `setLink`, `move`, `remove`, `setPriority`, `setItems`) writes localStorage, enqueues, and returns. Move callers over one at a time. The `*InFirebase` wrappers and the gotchas then go away.

### 13. [Low · Structure] `firebaseHelpers.tsx` mixes unrelated jobs and creates an import cycle
**Where:** [outbox.ts:5](../../src/utilities/sync/outbox.ts#L5) ↔ [firebaseHelpers.tsx:4](../../src/utilities/firebase/firebaseHelpers.tsx#L4)
**What happens:** One file holds the billing cache, DEK docs, idea-write wrappers and preferences. The outbox needs `getCachedBillingStatus`, and the file needs `enqueue`, so the two import each other.
**Fix:** Split into `billing/billingCache.ts`, `firebase/encryptionKeys.ts` and `firebase/preferences.ts`. The idea wrappers go into #12's store.

### 14. [Low · Structure] Constants and types that client and server must agree on are kept in two places
**Where:** `SUPPORT_EMAIL` ([src](../../src/utilities/support.ts), [functions](../../netlify/functions/lib/support.ts)); `profanityFilter.ts` (two identical copies); `BillingStatus` (client) vs `BillingDoc` (server, which already has two fields the client type lacks); `1499` in [pricingDisplay.ts:12](../../src/utilities/billing/pricingDisplay.ts#L12) and [lifetimePricing.ts:12](../../netlify/functions/lib/lifetimePricing.ts#L12); `TrackedIssue` in two functions; `50` in [firestore.rules:27](../../firestore.rules#L27) and `FREE_NODE_LIMIT`.
**What happens:** Each pair carries a "keep in sync" comment and nothing enforces it. A price change means editing two files.
**Fix:** Add a top-level `shared/` directory, plain TypeScript with no browser or Node imports, included by both `tsconfig.app.json` and `tsconfig.functions.json`. Netlify's esbuild bundles relative imports from outside `netlify/` fine. The rules literal can't import anything, so add a test that checks it against `FREE_NODE_LIMIT`.

## Structure overview
The layering is mostly sound and clearly deliberate. Pure cores (`sync/ops.ts`, `billingEvents.ts`, `importers.ts`/`exporters.ts`) are tested and kept separate from their I/O shells (`outbox.ts`, `stripe-webhook.ts`, `importIdeas.ts`). There is exactly one path that writes idea docs to Firestore, and the server owns billing. The design leaks in two places. First, idea mutations above the outbox have no single owner, so every component calls the localStorage write and the outbox write itself, and desktop and mobile each repeat that (#12). Second, code that client and server must agree on is copied by hand rather than shared (#14).

Best payoff for effort, in order:
1. **`ideaStore.ts` (#12).** It removes three documented gotchas, stops desktop and mobile drifting, and makes the `MobileMindMap` split (#17) mechanical.
2. **`shared/` for client/server constants and types (#14).** Small, and removes every "keep in sync" comment.
3. **`authedPost` wrapper for Netlify functions (#15).** It keeps the security fixes (#3, #6) in one place instead of nine.

Everything else in #13, #16 and #17 is cleanup you can do whenever you're in those files.
